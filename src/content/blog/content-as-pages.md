title: Контент как страницы сайта

Разрабатывая себе сайт-портфолио, я понял, что хочу хранить контент в виде Markdown. Я постоянно пользуюсь им, например, чтобы писать заметки или инструкции. К тому же редактировать обычный текст куда легче, чем компонент на сотни строк.

Конвертировать Markdown в React-компоненты оказалось не так сложно благодаря экосистеме unified. С помощью плагинов rehype и remark я смог добавить нужные мне кастомизации, например, подсветку синтаксиса.

Я начинал проект на Vite. По сравнению с Turbopack из Next.js он намного быстрее применял изменения и давал больший контроль над кодом. Мне не хотелось затягивать разработку и добавлять RSC, поэтому я решил использовать TanStack Start в качестве фреймворка. Я легко подключил пререндер и получил быструю загрузку страниц, а также оставил весь пайплайн преобразования Markdown на сборке.

На этом этапе я столкнулся с трудностями. Как уже говорилось, большая часть моего контента - Markdown-файлы. К сожалению, TanStack не умеет отдавать MDX как страницу. Единственное, что он предлагает - делить весь контент на коллекции и добавлять валидацию frontmatter на каждую из них. Меня это не устроило, потому что пришлось бы объединять в непонятную общую коллекцию страницы, находящиеся в корне. Мне это показалось неинтуитивным, и я сделал свое решение.

Физически в проекте есть один splat-роут в корне. Роутер не может сам понять, какие именно будут маршруты, и не выдает нужной типизации. Менять сгенерированные им файлы - не лучшая идея. Поэтому я написал Vite-плагин, который читает файлы в указанной директории и генерирует из них тип `PagePath`. Он срабатывает на каждое добавление и удаление файлов в `src/content`, чтобы сразу добавить нужный путь в тип:

```ts
export function scanPagePaths(root: string = CONTENT_DIR) {
  const byPath = new Map<string, string>();

  for (const file of scanContentFiles(root)) {
    const path = fileToPagePath(file);
    const taken = byPath.get(path);
    if (taken) throw new Error(`Content collision: "${taken}" and "${file}" both map to "${path}"`);
    byPath.set(path, file);
  }

  return [...byPath.keys()].sort();
}

export function contentPaths(): Plugin {
  return {
    name: "content-paths",
    buildStart() {
      generatePagePaths();
    },
    configureServer(server) {
      const onFsEvent = (file: string) => {
        if (isContentFileEvent(file)) generatePagePaths();
      };
      server.watcher.on("add", onFsEvent);
      server.watcher.on("unlink", onFsEvent);
      server.watcher.on("unlinkDir", (dir) => {
        if (isContentFolder(dir)) generatePagePaths();
      });
    },
  };
}
```

Также я добавил кастомный компонент ссылки, который определяет куда она ведет - на внутренний роут или на внешний источник. Если бы я оставил элемент `a`, страница перезагружалась бы при каждом переходе вместо клиентской навигации.

Сейчас, чтобы добавить страницу, я создаю файл в `src/content`. Дев-сервер перезапускать не нужно, `PagePath` пересобирается при добавлении или удалении файлов. Сгенерированный файл коммитится, иначе на свежем клоне проект не пройдет проверку типов до первого запуска. Вариант с несколькими коллекциями станет уместнее, когда появится несколько категорий со своими схемами frontmatter, а страницы вроде `index` или `about` перестанут выпадать из этой структуры.
