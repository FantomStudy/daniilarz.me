Разрабатывая себе сайт-портфолио, я понял что хочу хранить контент в виде Markdown. Я постоянно пользуюсь им, например, чтобы писать заметки или инструкции. К тому же редактировать обычный текст куда легче, чем какой-то компонент с большим количеством строк.

Конвертировать Markdown в React компоненты оказалось не так сложно, благодаря экосистеме `unifiedjs`. С помощью rehype и remark плагинов я смог добавить нужные мне кастомизации, например подсветка синтаксиса.

Я начинал проект на Vite, по сравнению с Turbopack из Next.js он намного быстрее применял изменения и давал больший контроль над кодом. Мне не хотелось затягивать разработку и добавлять RSC, поэтому я решил, использовать TanStack Start в качестве фреймворка. Я достаточно легко подключил пререндер и получил быструю загрузку страниц, а также оставил весь пайплайн преобразования Markdown на сборке.

На этом моменте я столкнулся с трудностями. Как уже говорилось, большая часть моего контента - Markdown файлы. К сожалению TanStack не умеет отдавать MDX как страницу. Единственное, что он предлагает - делить весь контент на коллекции и добавлять валидацию frontmatter на каждую из них. Меня это не устроило, потому что пришлось бы обьединять в непонятную общую коллекцию страницы, находящиеся в корне. Мне показалось это неинтуитивным и сделал свое решение.

Физически в проекте существует 1 splat роут в корне. Роутер не может сам понять, какие именно будут маршруты и не выдает нужной типизации. Менять сгенерированные им файлы - не лучшая идея. Поэтому я написал vite-плагин, который читает файлы в указанной директории и генерирует из них тип `PagePath`. Он срабатывает на каждое добавление и удаление файлов в указанной директории, чтобы сразу добавить нужный путь в тип:

```ts
export function scanPagePaths(root: string = CONTENT_DIR) {
  const byPath = new Map<string, string>();

  for (const file of scanContentFiles(root)) {
    const path = fileToPagePath(file);
    const taken = byPath.get(path);
    if (taken) throw new Error(`Content collision: "${taken}" and "${file}" both map to "${path}"`);
    byPath.set(path, file);
  }

  return [...byPath.keys()].sort();
}

export function contentPaths(): Plugin {
  return {
    name: "content-paths",
    buildStart() {
      generatePagePaths();
    },
    configureServer(server) {
      const onFsEvent = (file: string) => {
        if (isContentFileEvent(file)) generatePagePaths();
      };
      server.watcher.on("add", onFsEvent);
      server.watcher.on("unlink", onFsEvent);
      server.watcher.on("unlinkDir", (dir) => {
        if (isContentFolder(dir)) generatePagePaths();
      });
    },
  };
}
```

Также я добавил кастомный компонент ссылки, который определяет куда ведет указанное ссылка - внутренний роут или внешний источник. Если бы я оставил элемент `a`, то страница перезагружалась бы каждый переход, вместо мгновенного отклика.
