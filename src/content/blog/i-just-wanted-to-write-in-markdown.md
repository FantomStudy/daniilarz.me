Прошло некоторое время с тех пор, как я написал статью о том, как я [превращаю Markdown в страницы](/blog/content-as-pages). С ростом проекта я начал замечать недостатки и подводные камни моего решения.

Основной целью было удобное добавление контента. Тогда я подумал:

> Всё же очень просто. Почему бы мне не отдавать заранее подготовленный контент по совпадающему пути?

На тот момент времени страниц было не так уж много. Я сделал один splat-роут, который по адресу страницы находил нужный файл в папке `content/`. Это работало, но со временем выяснилось, сколько всего мне пришлось взять на себя:

1. **Сам типизировал пути**. TanStack видел всего один splat-роут. Чтобы компонент ссылки знал адреса Markdown-страниц, я написал Vite-плагин, который генерировал тип `PagePath`.
2. **Сам связывал адрес, метаданные и компонент страницы**. Заголовок и метаданные лежали в `PAGES`, компонент искался в отдельной таблице. Я сопоставлял их по URL и проверял, что у каждой записи есть компонент.
3. **Сам подключал стили страниц**. Галерея успевала появиться до того, как загружались её стили, и при загрузке прыгала. Чтобы это исправить, я искал CSS каждой страницы среди чанков сборки и добавлял ссылки на него в `<head>`.

Когда к метаданным и компонентам добавилась ещё и таблица стилей, мне стало тяжело держать в голове весь путь от Markdown-файла до страницы.
Код начал становиться громоздким и он был размазан повсюду.

Пересмотрев своё решение, я понял, что не заметил самого главного: я начал лезть на территорию фреймворка и идти в обход него. Тогда я остановился и подумал:

> Если фреймворк изначально предоставляет мне инструменты и оптимизации, то зачем я имитирую его работу и пытаюсь его заменить? TanStack уже умеет работать с обычными маршрутами. Что, если мой плагин будет генерировать сами маршруты?

Ровно так я и сделал. Я сохранил подход к генерации кода, но изменил то, что генерируется. Теперь Vite-плагин создаёт файл маршрута для каждого Markdown-файла. В нём указаны путь, метаданные и компонент страницы. TanStack Router сам генерирует типы путей, а TanStack Start добавляет ссылки на CSS маршрута в `<head>`. Список статей теперь берёт заголовки и даты из метаданных маршрутов.

Как пример, сгенерированный роут для главной страницы выглядит так:

```ts
/* oxlint-disable */
// AUTOGENERATED by vite/content/routes.ts from src/content/index.mdx — do not edit

import type { PageMeta } from "@/lib/meta";
import { createFileRoute } from "@tanstack/react-router";
import Content from "@/content/index.mdx";
import { pageHead } from "@/lib/meta";

const page: PageMeta = {
  path: "/",
  title: "Daniil Arz",
  art: "random",
};

export const Route = createFileRoute("/(content)/")({
  staticData: { page },
  head: () => pageHead(page),
  component: Content,
});
```

Если интересно, как плагин создаёт файлы маршрутов и удаляет устаревшие, тут можно посмотреть [код генератора](https://github.com/FantomStudy/daniilarz.me/blob/50256e8ab030840f5f38145cba57fae260113430/vite/content/routes.ts).

Чтобы добавить страницу, мне по-прежнему достаточно создать Markdown-файл. Только теперь я не переизобретаю колесо.
