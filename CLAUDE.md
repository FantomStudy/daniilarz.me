# Daniil Arz's portfolio

Daniil Arz's portfolio is a TanStack Start (React 19, SSR) app built around file-based content. Pages are added by dropping `.md` or `.mdx` files into `src/content/`, then turned into generated TanStack Router routes, rendered through a shared layout, and prerendered automatically at build time.

## What can't be compromised

- **Blazing-fast is measured, not assumed.** The site should feel fast everywhere, not just on a powerful desktop. Ship what measurements actually show — Lighthouse on mobile with throttling, across several runs — even when they contradict bundle-size intuition. DotsArt's statically imported `pixi.js` is the clearest example: the "obviously worse" larger bundle measured better TBT and a more stable Lighthouse score than the smaller, lazy-loaded version.

- **One source of truth per fact.** File↔URL mapping is defined by one function ([path.ts](vite/content/path.ts)) and applied once, at build time, when the content plugin writes each page's route; the router, `og/`, and the prerender list all read its result. A page's frontmatter lives in its generated route's `staticData`, which is how [PostList](src/components/PostList/PostList.tsx) lists pages. Keep it that way: no parallel page lists or second copies of the mapping that can drift apart.

- **Decorative work yields to the visitor.** `DotsArt` skips its WebGL/rAF work under `prefers-reduced-motion` and pauses when the tab is backgrounded — decoration must not cost users who didn't ask for it or aren't looking.

- **No content page is invisible to the prerenderer.** Every file under `src/content/` prerenders whether anything links to it yet or not — an unlinked page silently missing prerendering is a bug, not an edge case.

- **Prefer modern platform APIs.** Use modern web platform APIs when they are a good fit instead of reaching for older patterns or unnecessary abstractions — for example, the View Transitions API. Check browser support first: Temporal was tried and dropped because it isn't available everywhere yet, so dates use `Date`.

## The ways to hurt yourself

Each of these has happened before and was diagnosed and reverted.

- **Lazy-loading DotsArt's `pixi.js` import.** It looks like a bundle-size win, but measured worse TBT and a less stable Lighthouse score. Don't split it again on chunk-size grounds without measuring the actual impact.

- **Rendering `PageWrapper` from the generated page routes.** With seven importers, Rolldown moves it into a shared chunk whose CSS ships as a second render-blocking stylesheet, ordered before `index.css` — measured +150–300 ms FCP on every page. It belongs in the one hand-written layout, [(content)/route.tsx](<src/routes/(content)/route.tsx>); generated routes set `component` to the MDX content alone.

- **Treating every non-`/` `href` as an external link in [Link](src/components/Link.tsx).** This opens `mailto:` and `#` links in a blank tab.

- **Letting `fonts.css`'s relative `url()` and `__root.tsx`'s `?url` import resolve to different emitted files.** Vite emits the font twice, and the preload warms a URL the CSS never requests — costing 48 KB instead of saving it.

## Commands

Package manager is `bun`; the scripts themselves are in [package.json](package.json) (`dev`, `build`, `preview`, `lint` → `oxlint --fix`, `fmt` → `oxfmt`).

There is no test suite or runner in this repo — `bun run build` (which runs `tsc -b` first) is the only gate. To type-check without a full build: `tsc --noEmit -p tsconfig.app.json` for app code, or `-p tsconfig.node.json` for `vite.config.ts`, `vite/`, and `scripts/`.

## Taste

- Components are arrow-function expressions (`export const Foo = (...) => {...}`), not `function Foo()` declarations. The exception is route files in `src/routes/`: `export const Route = ...` goes first, and the components it references are hoisted `function` declarations below it, so the route's metadata reads top-down.
- Props are typed via a named `interface FooProps` declared above the component, not inline in the destructure.
- `clsx` for conditional/combined `className`s, not manual template-string concatenation.
- Comments are rare (see the root-level default: only when the _why_ is non-obvious) — and when one is warranted, it's written in Russian, matching the existing convention in e.g. [DotsArt.tsx](src/components/DotsArt/DotsArt.tsx). Identifiers, docs, and this file stay English; match whichever language a given file's existing comments already use rather than defaulting to English.

## Where code lives

- [src/routes/](src/routes/) — file-based routes; `__root.tsx` is the document shell. `(content)/` is a route group holding one generated route per content page (marked AUTOGENERATED, never hand-edited, committed so `tsc` passes on a fresh clone) next to the hand-written `route.tsx` layout; the generator only deletes files carrying its marker. The generated `src/routeTree.gen.ts` is never hand-edited either.
- [src/content/](src/content/) — every `.md`/`.mdx` page; a file's path is its URL.
- [src/lib/meta.ts](src/lib/meta.ts) — everything a page is described by: `Frontmatter`, `PageMeta` (frontmatter plus URL), the site origin, OG image size and path, and `pageHead` (the `<head>` tags every generated route uses).
- [src/components/](src/components/) — one directory per component (`Component.tsx` + `Component.module.css` + `index.ts`); [Link.tsx](src/components/Link.tsx)/[NotFound.tsx](src/components/NotFound.tsx) are flat exceptions.
- [src/styles/](src/styles/) — global CSS (`reset`, `fonts`, `index`, `markdown`), imported once from `__root.tsx`.
- [src/assets/fonts/](src/assets/fonts/) — self-hosted `.woff2` files, fingerprinted by Vite. [src/assets/og/](src/assets/og/) holds the committed Open Graph background.
- [vite/](vite/) — build-time Vite plugins: `content/` (`collect.ts` scans `src/content/` and reads frontmatter; `path.ts` holds every name derived from a content file — its URL, route id, and route file name, escaping router syntax and rejecting what the router can't escape, like `$`; `routes.ts` writes and prunes `src/routes/(content)/`; `index.ts` is the plugin, which re-syncs all routes in its `config` hook, so they exist before the router builds its tree, and on any change under `src/content/`) and `og/` (renders one OG image per page: `index.tsx` is the plugin, `Card.tsx` the card layout). Each plugin's `index` file is its only public entry, and the plugins don't import each other: `vite.config.ts` calls `collectPages()` (re-exported from `content/index.ts`) once and hands the list to `og()` and to the prerender/sitemap list. They import `src/lib/meta.ts` directly, so it must stay environment-neutral: no imports, no `@/` alias, no browser APIs — `tsconfig.node.json` (no DOM lib) enforces it.
